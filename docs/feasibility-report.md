# 百仓防腐验证 综合可行性评估 (P4)

> 职责边界: P3 "百仓防腐验证" 迭代的终态数据、适配成本复盘、病态类目与设计目标判定; 供 Wave 2 (Adapter 飞轮 / L2 路由) 立项决策。方法与规范见 [rule-format.md](rule-format.md), POC 阶段数据见 [poc-report.md](poc-report.md)。
> 执行时间: 2026-10-20 ~ 2026-10-21; 引擎/规则/语料三仓 CI 全绿。

## TL;DR

**设计目标在百仓规模上全部成立**: 124 个跨 25 栈示范项目 (123 仓产出语料 1318 样本) 上, 以 120 条规则 / 60 个工具达成 **FN=0 / FP 率 0.012% / 零块=0 / 双粒度压缩 99.28% / 99.65%**。适配成本侧, 全部规则增补 (90 条 / 45 工具, 批次 1~3 共 5 个 PR; 另有批次 0 的 1 个修复 PR) 由 agent 在一个工作日内完成, 每栈约 30-60 分钟 — **人工可行, 飞轮 (LLM Adapter) 更可行**。病态类目收敛为有限清单, 无一否定核心设计。

## 1. 验证方法

防腐验证 = 把 "规则正确性" 从作者自测升级为持续门禁:

1. **语料 refresh (GHA weekly)**: 自动抓取 124 示范项目各 ~8 失败 + ~3 成功 run 日志 (gzip 全量入库, orphan 单提交刷新, 仓体积恒定); 语料是规则正确性测试用例的**唯一 SSOT** (真实日志, 零合成样本)。
2. **门禁回测**: 引擎仓 CI (变引擎) 与规则仓 CI (变规则) 各自跑 L0 判定 — FN=0 / FP 率≤2% / 零块=0 / 边界违例=0 / 语料在场双下限; 压缩率双测防退化 (base vs PR 同语料同规则侧对比, 退化 >2% 判红)。
3. **豁免通道**: 新仓首刷标 `exempt: onboarding` 跳过 FN/FP/零块断言 (照常进报告), 逐仓消豁免 = 适配进度度量。本迭代消豁免 119+2 = **豁免清零**。

## 5. 设计目标逐项判定 (七项全部成立)

| 设计目标 | 依据 |

## 6. Wave 2 路线输入

1. **LLM Adapter**: 规格即 §3 的机械循环; 输入 FN 诊断报告, 输出规则草稿 PR + 回测报告。
2. **L2 repos/ 路由**: 项目层 `.log-skimmer/rules/` 叠加装载已就绪 (引擎 v2), 病态仓库可走 per-repo 覆盖而不膨胀全局规则集。
3. **语料槽位扩展**: 124→N 仓的边际成本仅为 projects.yaml 一行 (refresh 全自动); 空仓硬防线已放宽 (§4)。
4. **语料仓消费面**: 引擎 CI 已切 depth-1/fetch+reset 消费 orphan master; 新消费方须遵循同一模式。

## 7. 结论

百仓防腐验证通过。核心价值主张 — "把失败 CI 日志压缩为带坐标与语义注解的高信噪比摘要, 且这一质量被持续门禁保卫" — 在 25 栈 / 123 仓 / 1318 样本上成立; 适配成本画像支持飞轮自动化。无否定性发现, 进入 Wave 2。
