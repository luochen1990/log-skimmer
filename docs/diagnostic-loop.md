# 诊断闭环: 捕获失败真实原因的可持续自动化维护方案

> 职责边界: 本文是「诊断闭环」的**方案 SSOT** — 问题定义、三层机制分工、有效性指标与防灌水设计、运行期契约与演进路线 (issue #106)。
> 两侧实现细节各有其 SSOT, 本文不重复: 引擎侧口径 = `engine/src/l0.rs` 诊断缺口节注释 (清单谓词/候选行谓词/上限); 响应器剧本 = rules 仓 `.github/` (fn-responder 同模式)。
> 读者: 维护本仓 l0 判定面 / rules 仓响应器 / 消费 skim 输出做成败判定的人与 agent。

## 0. 术语

> 一句话定义如下, 完整语义以各行 SSOT 为准: 既有术语 → spec (`docs/rule-format.md`) 或 `engine/src/l0.rs` 模块注释; 本文新造术语 → 首次定义于此。

**既有术语 (沿用, 非本文发明)**:

| 语料 / 样本 | 真实 CI 日志的样本集 (独立仓, 每周自动滚动); 一个样本 = 日志文件 + sidecar (仓/结论/attempt 等元数据) 两件套 | spec §5 |

| diagnostic 级 | P_f ≤ 0.2: 只有特定失败模式才触发 — 触发本身携带「哪种失败」的信息 | l0.rs |

| fn-responder | 已部署的 FN 红事件自动响应链: 派遣门控差集判定 → 唤醒内网 agent → 起草规则 PR → 人工合并 (永不自动) | rules 仓 |
| 派遣门控 / 在途声明 / 冷却 | 唤醒集 = 本拍样本 − 上拍快照 − 在途 PR 声明 − 冷却拒绝样本; 稳态零发送 | rules 仓 |

## 1. 问题定义: 「有块」≠「捕获了原因」

issue #106 实例 (forgejo nixos CI): 失败日志中规则命中的只有编排层安全网 (`Job failed` 尾部信号 — **结论复述**, 零诊断信息), 而真正有信息量的行 (带轮询回显前缀的 nix store 错误树) 不被任何规则命中。

为什么既有门禁全绿却仍是盲区:

- **FN 断言只测完全漏检** (失败样本 failure-intent fragment = 0)。安全网兜底后 fragment ≥1, 断言恒绿 — 「部分漏检」永不触发。
- **诊断覆盖率是比值不是清单**。健康档案 (l0 规则分级: restating = 触发由结论决定的结论复述型 / diagnostic = 触发由内容决定 / boundary = 断裂带人工审) 已能量化「失败族 (failure|timed_out) 样本中含**非 restating** (diagnostic ∪ boundary) failure 命中的比例」— 公开语料实测 568/975 = 58.26% (2026-10-28): 四成失败样本的 skim 输出是「结论复述的 trivial 输出」。但比值答不了「哪个样本的哪些行是被漏掉的真实原因」。
- **fn-responder 只被 FN 红事件唤醒**。trivial 样本不产生任何事件。

一句话: 召回优先的结构承诺 (spec §0 零块=0) 保证「有块」, 但不保证「块里有原因」; 缺的是把 trivial **定位成清单**并**自动响应**的闭环。

### 1.1 指标阶梯: 每个指标回答一个正交问题

| 指标 | 回答的问题 | 强度 | 现状 |
| --- | --- | --- | --- |
| FN=0 / 零块=0 | 有没有块 (存在性) | 硬门禁 | 已部署 |
| FP 率 ≤2% | 块干不干净 (不污染成功日志) | 硬门禁 | 已部署 |
| 压缩率 | 块省不省 (读得少) | 双测防退化 | 已部署 |
| 诊断覆盖率 | 块里有没有信息 (有效性) | 软指标 → 清单 | 报告面; 清单化 = §2.1 |
| 诊断信息有效率 (抽样审计) | 块里是不是真因 (地面真值) | 抽样估计 + 偏离报警 | 缺口 (§4.2 D2) |

FN 与诊断覆盖率精确互补: FN 保证「有块」, 诊断覆盖率保证「块由内容决定」。
诊断覆盖率的已知局限 (维持软指标的原因): ① **代理性** — 「含诊断级命中」≠
「捕获了该样本的直接原因」(真因判定需地面真值, 统计免费拿不到, 见 §4.2 D2);
② **可灌水性** — 存在统计上 diagnostic 但零真因信息的灌水手法, 见 §4。

## 2. 三层机制

```text
                 ┌─── 度量层 (引擎 l0, 确定性, 本仓) ──────────────────────┐
 语料周滚动 ──▶  │ diagnostic_gaps 清单: 样本 × 候选行 (summary artifact)     │
                 └──────────────────┬─────────────────────────────────────┘
                                    ▼
                 ┌─── 响应层 (rules 仓, 维护期 AI) ────────────────────────┐
                 │ dg-responder: 差集去重 → 唤醒 agent → 起草规则 PR      │
                 │ (证据 KB 级离场, 语料永不离 runner — fn-responder 护栏)  │
                 └──────────────────┬─────────────────────────────────────┘
                                    ▼  PR 合并 → 缺口样本消失, 覆盖率上行
                 ┌─── 防腐层 (rules 仓 sweep, 确定性) ──────────────────────┐
                 │ 周漂移哨兵: 工具输出形态演化 → 新缺口样本 → 下一拍唤醒    │
                 └─────────────────────────────────────────────────────────┘
```

### 2.1 度量层 (引擎, 确定性 — 已交付)

`l0` summary 新增 `diagnostic_gaps` 数组: **逐样本清单**, 入选 = gated 域 (滤 rerun-through 与豁免样本的断言域) ∧ 失败族 (failure|timed_out) ∧ 非 FN (有 failure 命中, 完全漏检归 FN 断言管) ∧ failure-intent 命中中无一来自非 restating 规则。每条目携带:

- `repo / sample / conclusion / input_lines` — 定位 (与 fn detail 同一身份方案, 供差集去重);
- `hit_rules` — 该样本命中的全部 signal 规则 (典型形态: 仅安全网 — 响应端上下文);
- `candidates` — **缺口证据候选行**: 内置失败关键词命中 ∧ 未被任何 signal fragment 消费 (block 区间含折叠 frag_spans; context 不算) ∧ 未被 noise 剔除; 尾部优先取后 10 行, 单行摘录 ≤200 字符 (越界截断加省略号)。

口径 SSOT = `engine/src/l0.rs` 诊断缺口节注释; 谓词纯函数 + 分域语义有单测锁定。**运行期零变更**: skim/CLI/MCP 的行为与输出不动 — 度量只发生在维护面 (l0 报告), 不进门禁断言 (软指标)。

关键词集与 rules 仓 `fn-evidence.sh` 同源 (召回优先): 「0 failed」类良性命中会混入候选, 由响应端过滤 — 宁可多列不可漏列, 与 spec §0 召回优先同哲学。

### 2.2 响应层 (rules 仓, 维护期 AI)

**派遣判定 (dispatch gate, 确定性差集 — fn-responder v2 同构)**:

```text
唤醒集 = 本拍清单样本集
       − 上拍快照          (老缺口已唤醒过, 不重复叫醒)
       − 在途 PR 样本声明   (agent/gap-* 分支携带, 已派单未合并)
       − 冷却期拒绝样本     (人工裁过「不该造规则」, 防死循环)
```

前两项与 fn-dispatch-gate 同构; 第三项是 dg-responder **新语义** (fn-gate 的 12h 冷却是「合并了未痊愈」窗口, 本项是「人工拒绝后防重唤醒」登记 — 实现勿照抄)。

非空 → repository_dispatch 唤醒内网 agent; 空 → 零发送 (稳态零 token — 同一缺口在规则合入前每拍照旧红, 但只唤醒一次; 门禁的诚实红与唤醒的节约正交)。

**冷启动**: 首拍存量积压 (~400 样本) 不整批派单 — 首拍快照视为已唤醒, 此后仅对增量差集唤醒; 存量经 latest.md 报告面按仓分批领单 (同仓缺口常同因, 一张规则单可关多个样本), 证据包继承 fn-evidence 的总量预算护栏 (256KB)。

**Agent I/O 契约**:

| 端 | 内容 | 获取路径 |
| --- | --- | --- |
| 输入·清单 | repo/sample/conclusion/hit_rules/candidates (引擎侧已截断 ≤10 行/样本, ≤200 字符/行) | sweep 在 runner 上跑 l0 → summary artifact → 提取后随证据包发布 reports 分支 |
| 输入·环形上下文 | 候选行 ±N 行原文 | runner 上按 line_no 回语料现取后随证据包发布 (语料本体不离开 runner, 仅 KB 级摘录离场 — 与 fn-evidence 同护栏; 引擎输出保持「索引」定位, 内容窗口由响应层补) |
| 输入·规则集与 spec | 现有规则 YAML + 规则格式规范 | rules 仓本体 (避免 id 冲突 / 参考同族写法 / 判断「新规则」还是「现有规则加前缀容忍」) |
| 输出·主流 | 规则 PR: `agent/gap-*` 分支 + 规则 YAML (`attribution` 标注 generated-by, `# samples:` 溯源) + PR body 样本声明 (供差集) + 回链修复的清单条目 | → lint 门禁 → 人工合并 |
| 输出·拒绝 | 「人工分诊」标记: 候选为空 (失败无文本显著性) / 良性噪音 / 结构性失败的样本不硬凑规则 | → 冷却登记 |

拒绝路径是泄压阀: 没有它, 响应器会被覆盖率指标逼着写过拟合规则 (§4)。

**输出应用**: lint.yml 自动门禁 (装载校验 + FN=0 / FP 率 ≤2% / 零块断言 + master-vs-PR 压缩率双测) → 全绿 ≠ 自动合并, 停在人工 approve (W1b = FN 自动响应的部署代号, 其纪律: agent 起草的 PR 永不自动合并) → 合并后下拍 sweep 该样本获得诊断级命中, 退出清单, 覆盖率上行; PR 被拒则样本回差集, 受冷却约束。

### 2.3 防腐层 (rules 仓 sweep, 确定性)

规则腐化的每个向量都有确定性探测器, 周滚动语料保证新形态自动流入探测面:

| 腐化向量 | 探测器 | 响应 |
| --- | --- | --- |
| 规则完全失配 (工具输出改版) | FN 断言 (硬红) | fn-responder |
| 规则污染成功日志 | FP 率断言 (硬红) | 人工/lint 拒绝 |
| 规则永不触发 (拼写漂移) | per_rule_hits / dead_rules | 人工清理 |
| **诊断退化 (命中只剩结论复述)** | **diagnostic_gaps 清单 (软)** | **dg-responder (本方案新增)** |

诊断覆盖率不入硬门禁 (明确不做, 见 §5); 漂移哨兵 + 清单响应已是防腐机制本身。

## 3. 运行期契约 (零 AI 不变)

运行期 = 纯 regex 逐行状态机 (spec §0 设计灵魂 / §2 公理 A1-A8), 本闭环全部发生在维护面 — 「运行期脱离 AI Agent, 维护期适量使用」由结构保证而非纪律约定: AI 被夹在两层确定性之间 (前面是确定性缺口探测器, 后面是确定性统计门禁), 自始至终没有判断权。

消费方**今天即可用**的运行期实践 (零改动): skim 输出的 `blocks[].rules` 与已发布的 [rules-health.md](https://github.com/luochen1990/log-skimmer-rules/blob/reports/rules-health.md) restating 名单交叉 — 若全部 failure 块都来自 restating 规则, 视同「捕获 trivial」, 按 spec §3 判定矩阵的 fallback 纪律回退 rg 基线。

**Phase 2 提案 (待规则仓协调, 未实施)**: 规则字段显式声明安全网角色 (`role: safety_net`), 引擎在 skim 协议增加 trivial 捕获提示字段 (advisory — 零块是结构承诺走 exit 3, trivial 捕获是统计嫌疑只提示不阻断), 使消费方无需外挂健康数据源。新增字段须配引擎支持 (deny_unknown_fields 拒载语义) 与 manifest 版本协商, 落地节奏随 rules 仓采纳决定。

## 4. 有效性度量与防灌水 (指标-校验配对)

**结论先行**: 绝对不可灌水的代理指标不存在 (Goodhart: 任何被当作优化目标的代理量都会失真) — 「真因」的地面真值只存在于人的判断里, 统计只能代理。可达成的工程目标是**成本反转 + 留痕**: 灌水成本高于真实改进成本, 且每次灌水在公开数据面留下指纹。设计原则:

> **每个可被优化的代理指标, 必须配一个不可被同一手段优化的正交校验。**

FN/FP 的校验是 CI 元数据里的 job 结论 (日志内部伪造不了) — 所以能当硬门禁; 「真因」没有免费的外部真值, 只能抽样买 (D2)。

### 4.1 灌水面 (三种具体攻击, 共同点: 匹配「与结论共变、与真因无关」的常量型内容)

- **A 失败路径回显规则**: 匹配「失败才出现的编排层回显」(crash 工件上传提示 / 失败通知行 / teardown 消息) 的 niche 规则 — P(触发|成功)=0 不碰 FP 门禁, P(触发|失败)≤0.2 分级 diagnostic, 覆盖率 +1, 真因信息为零。
- **B 安全网拆分**: 把处处触发的 restating 安全网拆成 N 个互斥小片 (每片 ≤20% 失败样本), 每片单独过 diagnostic 线 — 并集覆盖不变, 覆盖率被纯指标手术推满, 语义零变化。
- **C 小样本伪相关**: 975 失败样本里「出现于 ≥2 失败 ∧ 0 成功」的随机字符串在多重比较下必然存在, 写成规则即 diagnostic — 当前分级为点估计且无最小触发数, a=2 ∧ b=0 即算数。

### 4.2 三层防线

**D1 统计加固 (引擎, 确定性 — 使 A/B/C 在分级处失效)**:

1. **分级小样本加固**: diagnostic 判定加最小触发数 (a ≥ A_MIN), 且判级所用的 P_f/P_s 以区间保守化 (下界/上界, 具体统计量与 A_MIN 在落地 issue 于真实语料定标) — 攻击 C 的廉价小样本覆盖出局。
2. **内容变异性判据** (content variability): 对规则在全语料上消费的全部样本行统计 `distinct / total` 比值 — 直接度量「匹配内容携带的样本级信息量」。比值趋近 0 (所有命中行几乎相同) 的规则判为**常量型**: 匹配内容对所有样本同构 = 零样本级信息, 不计诊断覆盖分子 (仍是合法规则 — 服务零块防线与定位)。回显串 (A) / 安全网碎片 (B) / 常量串 (C) 的命中行全部同构 → 比值趋 0 → 三种攻击一次失效。真实工具证据的命中行天然多样 — 且**刻意不做变量归一化** (不剥 hash/路径): 变量部分本身就是消费方使用的信息 (哪个文件/哪个单元), 归一化会把 `error: opening file '<hash>'…` 这类有效规则误判为常量 (需求方裁决 2026-10-28)。该判据把 restating 检测从「与结论的相关」深化到「匹配内容的信息量」— 无论有无攻击者都让指标更有效。已知局限 (保守方向可接受): 少数真实因果标记行本身是常量 (`Segmentation fault` / `Killed`) — 会被判常量型退出覆盖分子; 假降级只低估覆盖率 (安全), 假升级才灌水 (危险), 此类规则经 D2 审计/人工视角校正。

**D2 抽样审计 (人因, 周检分钟级 — 唯一的真值锚)**: 每周抽 k 个「本周新退出清单」样本 + k 个对照, 人工二元判定「skim 输出是否指出可行动的真因」→ 估计**诊断信息有效率** (带置信区间) 与诊断覆盖率并列发布; 两指标持续偏离 = 灌水或漂移**报警** (只报警不自动红 — 审计不裁决, 裁决仍归确定性门禁)。审计标签在规则 PR review 中已半自然积累 (人工 approve 隐含「该命中是真因」标注), 抽样把它系统化。

**D3 流程透明 (已大半在场)**: 规则 PR 回链修复的清单条目 (无缺口出处的规则须解释存在理由) / 永不自动合并 / 逐规则健康表公开 — 灌水留下指纹 (常量型与离群规则在健康表上一目了然)。

### 4.3 目标评估与已知缺陷

「不可灌水」按绝对意义不可达; 按「灌水成本 > 真实改进成本 ∧ 灌水可检测」可达 — D1 使最廉价的常量型灌水在分级处确定性失效; D2 使残余的「变内容但因果无关」型灌水 (如匹配失败 job 名) 以抽样概率暴露; D3 使一切动作可追溯。已知缺陷登记: D1 的 distinct/total 判在 A0 行归一化后的文本上 — 归一化未覆盖的无信息变体 (如行内时间戳) 会抬高比值, 让灌水规则逃逸常量型判定 (该向量由 D2 抽样兜底, 标定暴露后归 A0 演进), 阈值须在真实语料上标定; D2 的审计者若即起草 agent 的操作者则防线名存实亡 (轮换/双人复核属组织纪律, 不在工程面内)。

## 5. 边界与明确不做

- **覆盖率不入硬门禁**: grade 是语料组合相关的统计量 (同一规则在混合语料与单一语料下分级可漂移), 硬阈值会随语料构成漂移; 且 FN/FP 已是硬警察, 清单是响应面不是判定面。硬棘轮待 D1 加固 + D2 校准落地、覆盖率语义稳定后另议。
- **不造语料生造物**: 清单消费真实语料 (语料仓快照); 引擎侧测试用内存直测与最小构造件 (AGENTS.md 语料边界纪律)。
- **豁免样本不入清单**: 未适配仓的缺口由豁免余量 (适配进度) 跟踪, 不混入响应器 — 两类缺口两个通道。
- **cancelled 不入清单**: 截断日志证据不可靠 (三态 = 结论的证据能力分层: skipped 无日志全排除 / cancelled 截断只记命中不记缺失 / 成败家族全量计)。
- **内网语料不进清单流**: dg-responder 消费的 sweep 跑公开语料仓; forgejo 内网语料 (如 #106 实例) 的 diagnostic_gaps 在本仓 ci-merge 报告面暴露, 走本仓 issue 人工通道 (隐私红线: 内网样本不入 rules 仓清单流) — #106 实例修复因此是手工项 (§6)。
