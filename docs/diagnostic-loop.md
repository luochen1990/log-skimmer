# 诊断闭环: 捕获失败真实原因的可持续自动化维护方案

> 职责边界: 本文是「诊断闭环」的**方案 SSOT** — 问题定义、三层机制分工、运行期契约与演进路线 (issue #106)。
> 两侧实现细节各有其 SSOT, 本文不重复: 引擎侧口径 = `engine/src/l0.rs` 覆盖缺口节注释 (工单谓词/候选行谓词/上限); 响应器剧本 = rules 仓 `.github/` (fn-responder 同模式)。
> 读者: 维护本仓 l0 判定面 / rules 仓响应器 / 消费 skim 输出做成败判定的人与 agent。

## 1. 问题定义: 「有块」≠「捕获了原因」

issue #106 实例 (forgejo nixos CI): 失败日志中规则命中的只有编排层安全网 (`Job failed` 尾部信号 — **结论复述**, 零诊断信息), 而真正有信息量的行 (带轮询回显前缀的 nix store 错误树) 不被任何规则命中。

为什么既有门禁全绿却仍是盲区:

- **FN 断言只测完全漏检** (失败样本 failure-intent fragment = 0)。安全网兜底后 fragment ≥1, 断言恒绿 — 「部分漏检」永不触发。
- **诊断覆盖率是比值不是工单**。健康档案 (l0 规则分级 restating/diagnostic) 已能量化「失败样本中含诊断级命中的比例」— 公开语料实测 568/975 = 58.26% (2026-10-28): 四成失败样本的 skim 输出是「结论复述空心」。但比值答不了「哪个样本的哪些行是被漏掉的真实原因」。
- **fn-responder 只被 FN 红事件唤醒**。空心样本不产生任何事件。

一句话: 召回优先的结构承诺 (§0 零块=0) 保证「有块」, 但不保证「块里有原因」; 缺的是把空心**定位成工单**并**自动响应**的闭环。

## 2. 三层机制

```text
                 ┌─── 度量层 (引擎 l0, 确定性, 本仓) ──────────────────────┐
 语料周滚动 ──▶  │ coverage_gaps 工单: 样本 × 候选行 (summary artifact)     │
                 └──────────────────┬─────────────────────────────────────┘
                                    ▼
                 ┌─── 响应层 (rules 仓, 维护期 AI) ────────────────────────┐
                 │ gap-responder: 差集去重 → 唤醒 agent → 起草规则 PR      │
                 │ (证据 KB 级离场, 语料永不离 runner — fn-responder 护栏)  │
                 └──────────────────┬─────────────────────────────────────┘
                                    ▼  PR 合并 → 缺口样本消失, 覆盖率上行
                 ┌─── 防腐层 (rules 仓 sweep, 确定性) ──────────────────────┐
                 │ 周漂移哨兵: 工具输出形态演化 → 新缺口样本 → 下一拍唤醒    │
                 └─────────────────────────────────────────────────────────┘
```

### 2.1 度量层 (引擎, 确定性 — 已交付)

`l0` summary 新增 `coverage_gaps` 数组: **逐样本工单**, 入选 = gated 域 ∧ 失败族 ∧ 非 FN ∧ failure-intent 命中中无一来自非 restating 规则。每条目携带:

- `repo / sample / conclusion / input_lines` — 定位 (与 fn detail 同一身份方案, 供差集去重);
- `hit_rules` — 该样本命中的规则 (典型形态: 仅安全网 — 响应端上下文);
- `candidates` — **缺口证据候选行**: 内置失败关键词命中 ∧ 未被任何 signal fragment 消费 (block 区间含折叠 frag_spans; context 不算) ∧ 未被 noise 剔除; 尾部优先取后 10 行, 单行摘录 ≤200 字符 (越界截断加省略号)。

口径 SSOT = `engine/src/l0.rs` 覆盖缺口节注释; 谓词纯函数 + 分域语义有单测锁定。**运行期零变更**: skim/CLI/MCP 的行为与输出不动 — 度量只发生在维护面 (l0 报告), 不进门禁断言 (软指标)。

关键词集与 rules 仓 `fn-evidence.sh` 同源 (召回优先): 「0 failed」类良性命中会混入候选, 由响应端过滤 — 宁可多列不可漏列, 与 spec §0 召回优先同哲学。

### 2.2 响应层 (rules 仓, 维护期 AI)

gap-responder = fn-responder (W1b) 模式复用, 仅唤醒面从「FN 红事件」换成「新缺口样本差集」:

1. sweep 每拍从 l0 summary artifact 提取 `coverage_gaps`;
2. 差集判定 (本拍工单 − 上拍快照 − 在途规则 PR 声明) — 稳态零发送, 下游零 token 消耗;
3. 非空 → dispatch 唤醒内网 agent; agent 消费工单的 `candidates` (KB 级, 已截断/摘录 — 语料本体不出 runner), 起草规则 PR;
4. PR 走 lint 门禁 (master-vs-PR 双测), **永不自动合并** (W1b 纪律不变);
5. 合并后该样本的诊断级命中建立 → 退出工单 → 覆盖率单调上行。

### 2.3 防腐层 (rules 仓 sweep, 确定性)

规则腐化的每个向量都有确定性探测器, 周滚动语料保证新形态自动流入探测面:

| 腐化向量 | 探测器 | 响应 |
| --- | --- | --- |
| 规则完全失配 (工具输出改版) | FN 断言 (硬红) | fn-responder |
| 规则污染成功日志 | FP 率断言 (硬红) | 人工/lint 拒绝 |
| 规则永不触发 (拼写漂移) | per_rule_hits / dead_rules | 人工清理 |
| **诊断退化 (命中只剩结论复述)** | **coverage_gaps 工单 (软)** | **gap-responder (本方案新增)** |

诊断覆盖率不入硬门禁 (明确不做, 见 §4); 漂移哨兵 + 工单响应已是防腐机制本身。

## 3. 运行期契约 (零 AI 不变)

运行期 = 纯 regex 状态机 (spec §0), 本闭环全部发生在维护面 — 「运行期脱离 AI Agent, 维护期适量使用」由结构保证而非纪律约定。

消费方**今天即可用**的运行期实践 (零改动): skim 输出的 `blocks[].rules` 与已发布的 [rules-health.md](https://github.com/luochen1990/log-skimmer-rules/blob/reports/rules-health.md) restating 名单交叉 — 若全部 failure 块都来自 restating 规则, 视同「捕获空心」, 按 §3 判定矩阵的 fallback 纪律回退 rg 基线。

**Phase 2 提案 (待规则仓协调, 未实施)**: 规则字段显式声明安全网角色 (如 `role: floor`), 引擎在 skim 协议增加 floor-only 功告字段 (advisory — 零块是结构承诺走 exit 3, 空心是统计嫌疑只提示不阻断), 使消费方无需外挂健康数据源。新增字段须配引擎支持 (deny_unknown_fields 拒载语义) 与 manifest 版本协商, 落地节奏随 rules 仓采纳决定。

## 4. 边界与明确不做

- **覆盖率不入硬门禁**: grade 是语料组合相关的统计量 (同一规则在混合语料与单一语料下分级可漂移), 硬阈值会随语料构成漂移; 且 FN/FP 已是硬警察, 工单是响应面不是判定面。硬棘轮待覆盖率长期稳定后另议。
- **不造语料生造物**: 工单消费真实语料 (语料仓快照); 引擎侧测试用内存直测与最小构造件 (AGENTS.md 语料边界纪律)。
- **豁免样本不入工单**: 未适配仓的缺口由豁免余量 (适配进度) 跟踪, 不混入响应器 — 两类缺口两个通道。
- **cancelled 不入工单**: 截断日志证据不可靠 (三态: 只记命中不记缺失)。
